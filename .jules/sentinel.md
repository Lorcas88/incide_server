## 2024-04-01 - [Missing Null Check on Login Causes User Enumeration]
**Vulnerability:** A missing null check on the `user` object in the login flow caused a `TypeError` (resulting in a 500 error) when an attacker attempted to log in with an email that did not exist in the database, whereas attempting to log in with an existing email and wrong password returned a generic 401 error. This allowed attackers to enumerate registered users based on the different HTTP status codes.
**Learning:** Even when using timing attack protections (e.g., dummy hashes), logic checks on database query results (like checking an account lockout status) must account for the case where the user record does not exist to maintain a consistent response format for invalid credentials.
**Prevention:** Always verify that a returned object from a database query exists (`if (user && ...)`) before accessing its properties, especially in authentication flows where consistency is key to preventing enumeration attacks.
