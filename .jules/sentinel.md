## 2026-02-02 - Stored XSS in User Names via Email Templates
**Vulnerability:** User `first_name` and `last_name` fields were not sanitized/validated during registration or updates. These fields are directly interpolated into HTML email templates, allowing Stored XSS / HTML Injection.
**Learning:** Developers properly escaped ticket content but overlooked user profile fields, likely assuming names wouldn't contain malicious HTML or wouldn't be rendered in a dangerous context. However, emails are HTML contexts.
**Prevention:** Enforce input validation by rejecting characters used in HTML tags (specifically `<` and `>`) for name fields. While `.escape()` is a valid approach, it corrupts legitimate names containing apostrophes (e.g., "O'Connor" -> "O&#x27;Connor") if output decoding is not handled everywhere. A strict blocklist or whitelist for names is preferred when data integrity is paramount.
