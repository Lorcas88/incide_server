## 2026-05-05 - [Auth] Prevent User Enumeration via 500 Error Difference
**Vulnerability:** The `loginUser` service function previously attempted to check `user.locked_until` before verifying if the `user` object existed. This caused a `TypeError` (resulting in a 500 Internal Server Error response) when attempting to log in with an email that did not exist in the database. Attackers could observe the difference between a 500 error (user does not exist) and a 401 error (user exists but incorrect password) to enumerate registered users.
**Learning:** Checking properties on potentially null objects in authentication flows can inadvertently lead to user enumeration vulnerabilities by throwing unhandled exceptions which differentiate the error response logic from normal incorrect credential checks.
**Prevention:** Always verify the existence of the entity (e.g., `user`) before accessing its properties during authentication processes to ensure a constant code path or generic error messages (401) are returned for both invalid users and invalid passwords.
