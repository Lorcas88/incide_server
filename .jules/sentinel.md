## 2024-05-24 - [Null Pointer Exception Enables User Enumeration and Timing Attacks]
**Vulnerability:** A `TypeError` occurred during the login process when attempting to access the `locked_until` property of a null `user` object (caused when the provided email does not exist in the database). This crashed the request, returning a 500 Internal Server Error instead of a 401 Unauthorized, and completely circumvented the constant-time `bcrypt` comparison (timing attack protection) implemented immediately below.
**Learning:** Even though timing attack protections were explicitly coded, a simple null pointer dereference earlier in the execution flow exposed the very vulnerability it sought to prevent. This allowed attackers to enumerate existing users by distinguishing between 500 errors (non-existent email) and 401 errors (existing email with wrong password).
**Prevention:** Always verify that an object exists before accessing its properties, especially in critical security paths like authentication where error states must remain consistent.
