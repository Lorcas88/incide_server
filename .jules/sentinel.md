## 2024-04-11 - [CRITICAL] Fix user enumeration via TypeError in login
**Vulnerability:** In `src/modules/auth/auth.service.js`, the login function attempted to access `user.locked_until` without verifying that the `user` object existed. When an invalid email was provided, `user` was null, leading to an unhandled `TypeError`. This error response difference could allow an attacker to enumerate valid user accounts by observing which login attempts threw 500 server errors vs. 401 invalid credentials errors.
**Learning:** Always verify object existence before accessing properties, especially in sensitive authentication flows where error differences could leak information about account existence. Timing attack mitigation techniques (like using a dummy hash) are insufficient if the application crashes before the constant-time operation completes.
**Prevention:** Employ explicit null checks (e.g., `if (user && user.prop)`) or optional chaining (`?.`) when evaluating properties of objects that may be undefined or null due to database lookups not finding a match.
