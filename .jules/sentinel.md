## 2024-05-18 - [Fix Authentication User Enumeration via 500 TypeError]
**Vulnerability:** A missing null check on the `user` object in `loginUser` (`src/modules/auth/auth.service.js`) resulted in a `TypeError: Cannot read properties of null (reading 'locked_until')` when an unrecognized email address was provided. This caused a `500 Internal Server Error`, while valid users with incorrect passwords correctly returned a `401 Unauthorized` error.
**Learning:** This discrepancy between 500 and 401 response codes allowed attackers to enumerate valid email accounts by observing the status codes on failed logins. Attempting to verify account lockout status before checking the password or whether the user exists introduces this risk if the `user` is not checked for nullity first.
**Prevention:** Always verify that an object exists (e.g., `if (user && user.property)`) before attempting to access its properties, particularly in authentication flows where error discrepancies can lead to information disclosure.
