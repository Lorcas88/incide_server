## 2024-05-30 - [SQL Injection via Dynamic Object Keys in Query Builder]
**Vulnerability:** The `findOne` method in the base model (`BaseModel`) accepted an object of conditions and directly interpolated the keys into the query builder string using template literals (``this.where(`${this.table}.${key} = ?`, [values[index]])``). By passing an object with a manipulated key such as `{ "id = 1 OR 1=1 --": "test" }`, it was possible to alter the query logic and bypass intended filtering constraints (SQL injection).
**Learning:** Even when utilizing a query builder and binding values (e.g., using `?` placeholders for parameterized inputs), structural parts of a SQL query such as column names (keys) are not parameterized. Allowing unvalidated, unsanitized, or dynamic user input to determine object keys that construct these structural parts bypasses the protection parameterization offers for values.
**Prevention:** Always strictly validate and sanitize dynamic object keys before utilizing them in query generation. Utilizing a rigorous allowlist approach, such as a regular expression enforcing standard alphanumeric and underscore naming conventions (e.g., `/^[a-zA-Z0-9_]+$/`), ensures only structurally safe and valid column names can be utilized, preventing arbitrary SQL manipulation.
