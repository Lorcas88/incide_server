## 2024-04-09 - [Account Enumeration Vulnerability]
**Vulnerability:** In `src/modules/auth/auth.service.js`, the code accesses `user.locked_until` on the potentially undefined `user` object if the user does not exist. This would throw a `TypeError: Cannot read properties of null (reading 'locked_until')`, resulting in a 500 error instead of a 401 error. An attacker could use this difference in HTTP status codes to enumerate which email addresses exist in the system (since a nonexistent user causes a 500 error, while an existing user with wrong credentials causes a 401).
**Learning:** Checking properties on objects retrieved from a database without first verifying the object exists can lead to TypeErrors that leak information via error handling differences.
**Prevention:** Always ensure the object exists (e.g., `user && user.locked_until`) before attempting to access its properties, especially in authentication flows where timing and error responses must be consistent.
