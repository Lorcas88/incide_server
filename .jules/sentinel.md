## 2024-05-10 - [Account Lockout User Enumeration Vulnerability]
**Vulnerability:** A `TypeError` occurs when attempting to log in with an email that does not exist in the database, because `user` is undefined, but the account lockout check tries to access `user.locked_until`. This unhandled exception results in a 500 error for non-existent users, while existent users return a 401 error. This difference allows an attacker to enumerate valid user accounts by observing the HTTP status code.
**Learning:** Always verify that an object exists before attempting to access its properties, especially in authentication logic, to ensure consistent and safe error handling that prevents user enumeration. Error states must be handled cleanly to avoid leaking information about the system's internal state or data existence.
**Prevention:** Implement optional chaining (`user?.locked_until`) or explicit existence checks (`user && user.locked_until`) when accessing properties of objects that might be null or undefined. Additionally, write tests to assert that both valid and invalid login attempts return the expected generic 401 response without exposing internal errors.
