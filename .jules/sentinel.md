## 2025-04-25 - [SQL Injection and User Enumeration Vulnerabilities]
**Vulnerability:** Found a potential SQL injection vulnerability in `src/core/base.model.js`'s `findOne` method, where object keys were directly interpolated into SQL queries. Additionally, found a user enumeration flaw and potential server crash (`TypeError`) in `src/modules/auth/auth.service.js` where the login flow attempted to read `user.locked_until` before checking if the user object existed.
**Learning:** Dynamic keys used in ORM/query builder methods that get interpolated into SQL must be strictly validated. The codebase custom query builder did not restrict condition keys. Additionally, attempting to mitigate timing attacks by executing `bcrypt.compare` even when a user isn't found is great, but code after that which references the non-existent user must include null checks.
**Prevention:** Always validate condition keys dynamically passed to SQL builders using an alphanumeric/underscore regex (e.g., `/^[a-zA-Z0-9_]+$/`). Ensure proper null checking (`user && user.property`) when referencing objects returned from database queries, especially in authentication logic paths that handle invalid credentials gracefully.
