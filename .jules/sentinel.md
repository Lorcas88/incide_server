## 2024-05-24 - [User Enumeration via Unhandled TypeError in Authentication]
**Vulnerability:** In `loginUser` (`src/modules/auth/auth.service.js`), an attempt to access `user.locked_until` without checking if the `user` object exists was causing a `TypeError` (resulting in a 500 Internal Server Error) when an invalid email was provided. This difference in HTTP status codes allowed an attacker to enumerate which emails exist in the database, defeating the timing attack protections in place.
**Learning:** Even when incorporating timing attack protections like a constant-time comparison with a dummy hash, simple unhandled errors in surrounding logic (like accessing a property on `null`) can inadvertently expose valid users via different HTTP responses.
**Prevention:** Always verify that the retrieved object (`user`) exists before accessing its properties, especially in sensitive flows like authentication where consistent error handling is paramount to prevent information leakage.
